## 1. 문제 — "AI 티"의 정체

주관적 인상이 아니라 재현 가능한 원인이 있다. `ui-ux-pro-max` 디자인 DB에서
**"Personal Finance Tracker"의 1순위 추천 스타일이 `Glassmorphism + Dark Mode (OLED)`** 다
(`data/products.csv:91`). 즉 지금 앱의 외형 — 검정 배경 + 골드 그라디언트 + 글로우 + 유리 블러 — 은
생성 도구가 "가계부 앱"이라는 입력에 대해 내놓는 **기본값 그 자체**다. 같은 DB의 팔레트도 전부
Tailwind 기본 램프(`#0F172A`/`#3B82F6`/`#F8FAFC`)라 그대로 채택하면 같은 함정에 다시 빠진다.

현재 코드에서 그 클리셰가 있는 위치:

| 위치 | 클리셰 |
|---|---|
| `body::before` | radial-gradient 앰비언트 광원 2개 |
| `.hd-t` | 제목에 골드 그라디언트 + `background-clip:text` |
| `.acct-tot` | 골드 그라디언트 카드 + 6rem `₩` 워터마크 + 원형 하이라이트 |
| `.logo-s` `.fab` `.submit` | 그라디언트 배경 + 컬러 glow 그림자 |
| `.hd` `.nav` `.s-top` | `backdrop-filter: blur(32px)` |
| 전역 | `font-weight:900` 남발, 한글 라벨에 `text-transform:uppercase` |

부수적으로 라이트 모드가 아예 없다. `:root` 토큰이 다크 값 하나뿐이라
`prefers-color-scheme`을 무시하고 항상 검정으로 뜬다.

### 채택한 방향

DB는 **"피할 것"의 근거**로 쓰고, 방향은 같은 DB가 Banking/Traditional Finance에 추천하는
`Minimalism + Accessible & Ethical` (`products.csv:42`, `styles.csv:1,8`)에서 가져온다.

> **차분한 은행형 (Muted Bank)** — 순백 배경, 카드 박스 대신 1px 룰선,
> 그림자·그라디언트·블러 0, **액센트는 무채색**, 색은 손익에만.

목업으로 렌더해 승인받았다(`docs/superpowers/2026-08-24-light-redesign-mockup.html`, 390px 모바일 뷰포트, 6장).

## 3. 디자인 토큰

`:root`에 라이트를 정의하고, `@media (prefers-color-scheme: dark)`에서 **같은 이름을 재정의**한다.
컴포넌트 CSS는 토큰만 참조한다 — 셀렉터 안에 생 hex를 두지 않는다(§7 검사가 잡는다).

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--bg` | `#FFFFFF` | `#101215` | 페이지 배경 |
| `--fill` | `#F4F4F2` | `#1E2126` | 아이콘 웰·칩·트랙 |
| `--fill-2` | `#EAEAE7` | `#262A30` | 진행바 트랙·눌림 |
| `--ink` | `#14161A` | `#E9EBEE` | 본문·제목·**액센트** |
| `--ink-2` | `#5A6068` | `#A2A8B0` | 보조 텍스트 |
| `--ink-3` | `#8A9099` | `#767D86` | 마이크로 라벨 |
| `--line` | `#E4E5E7` | `#272B31` | 1px 룰선 |
| `--line-2` | `#CFD2D6` | `#373C44` | 강한 구분·테두리 |
| `--exp` | `#C0392B` | `#FF7A6B` | **지출 금액 — 오직 이 뜻** |
| `--inc` | `#0F6B4F` | `#4FCB96` | **수입 금액 — 오직 이 뜻** |
| `--warn` | `#9A5B14` | `#D9A054` | 한도 임박 |
| `--on-ink` | `#FFFFFF` | `#101215` | 잉크 채움 위 글자 |

배경 대비 — WCAG 상대휘도로 **계산해서** 넣은 값이다(눈대중 아님):

| | 라이트 (`#FFFFFF`) | 다크 (`#101215`) |
|---|---|---|
| `--ink` | 18.11:1 | 15.71:1 |
| `--ink-2` | 6.35:1 | 7.83:1 |
| `--ink-3` | 3.22:1 | 4.51:1 |
| `--exp` | 5.44:1 | 7.37:1 |
| `--inc` | 6.49:1 | 9.22:1 |
| `--warn` | 5.41:1 | 8.14:1 |
| `--on-ink` on `--ink` | 18.11:1 | 15.71:1 |

`--ink-3`가 라이트에서 3.22:1인 것은 의도다 — 현행 `--t3`와 같은 정책(마이크로 라벨·비텍스트 전용,
본문 금지). 나머지는 전부 AA 본문 기준(4.5:1)을 넘는다.

### 왜 액센트가 무채색인가

지출=빨강 / 수입=초록을 고정하면, 액센트에 초록을 쓰는 순간 **초록이 "수입"과 "선택됨" 두 뜻**을 갖는다.
분류 탭의 초록 배지, 한도 바의 초록이 각각 무엇을 뜻하는지 알 수 없어진다.
그래서 선택 상태는 색이 아니라 **잉크 채움 · 밑줄 · 굵기**로 표시한다.
결과적으로 화면에 나오는 색은 금액과 차트뿐이고, 금액이 유일하게 튄다.

## 4. 타이포그래피

폰트는 Pretendard Variable 하나 그대로다(성능 기준선 유지 — 새 폰트를 추가하지 않는다).
차별화는 **variable 축의 굵기 · 크기 · 자간 규율**로 만든다.

| 역할 | 크기 | 굵기 | 자간 |
|---|---|---|---|
| 총자산 등 히어로 숫자 | 2.125rem | 700 | -0.045em |
| 요약 금액 | 1.1875rem | 700 | -0.03em |
| 섹션 제목 | 0.8125rem | 650 | -0.01em |
| 리스트 항목명 | 0.9375rem | 500 | -0.01em |
| 금액 | 0.9375rem | 600 | -0.02em |
| 보조 텍스트 | 0.8125rem | 450 | — |
| 마이크로 라벨 | 0.6875rem | 600 | +0.01em |

규칙 3가지:
- **`font-weight:900` 금지.** 최대 700. 900은 화면을 무겁게만 만들고 위계를 못 만든다.
- **한글에 `text-transform:uppercase` 금지.** 효과가 없으면서 `letter-spacing`만 어색해진다. 전량 제거.
- `font-variant-numeric: tabular-nums` 유지(금액 세로 정렬).

## 7. 차트

`dataviz` 스킬의 절차를 따른다. 색은 마지막에 정하고, **검증기로 계산한다**.

### 7.1 팔레트 (검증 완료)

`scripts/validate_palette.js` 6검사를 **실제 서피스 색**으로 — 라이트 `#FFFFFF` · 다크 `#101215`
(카드 서피스를 없앴으므로 차트가 앉는 면은 `--bg`다) — 양쪽에서 실행해 전 항목 PASS를 확인했다.

| 슬롯 | 라이트 | 다크 |
|---|---|---|
| `--s1` | `#2a78d6` | `#3987e5` |
| `--s2` | `#eb6834` | `#d95926` |
| `--s3` | `#1baf7a` | `#199e70` |
| `--s4` | `#eda100` | `#c98500` |
| `--s5` | `#e87ba4` | `#d55181` |
| `--s6` | `#4a3aa7` | `#9085e9` |

- 라이트 worst adjacent CVD ΔE 9.1 / normal ΔE 19.6 · 다크 8.4 / 19.3 (기준 각각 ≥8, ≥15)
- 라이트에서 `--s3`·`--s4`·`--s5`가 흰 배경 대비 3:1 미만 → **relief rule 적용**:
  범례에 **이름 + 금액 + 퍼센트를 직접 라벨**로 붙여 식별이 색에만 의존하지 않게 한다
- **지출 빨강·수입 초록은 시맨틱 예약색**이라 카테고리 슬롯으로 재사용하지 않는다
  (참조 팔레트의 red/green 슬롯을 뺀 이유)

### 7.2 색 배정 — 순환을 없앤다

현재 `catColor()`는 `CAT_PALETTE[i % 12]`로 **순환**한다. 카테고리가 20개 가까운데 안전한 색은 6개뿐이라
그대로 `% 6`으로 줄이면 충돌이 잦아진다. 대신 **차트에 그리는 계열 수를 6개로 제한**한다:

- `viewAnalysis`가 이미 계산하는 `catTotals`(표시 주기 전체합 내림차순)의 **상위 5개에 슬롯 1–5를 고정 배정**하고,
  나머지는 전부 **`기타` = `--ink-3` 무채색**으로 접는다
- 이 매핑 하나를 **도넛 · 스택막대 · 추이라인 3개 차트가 공유**한다 → 한 화면 안에서 같은 카테고리는 같은 색
- 현행 코드와의 차이: 스택막대는 `TOPN` 6 → 5, 추이는 이미 상위 5, **도넛만 상한이 없어 새로 추가**한다
  (`_anStash.donut = curCatArr` 전량 → 상위 5 + 기타)
- 남는 트레이드오프(문서화): 멤버 필터를 바꿔 상위 5의 **구성원**이 달라지면 색이 이동할 수 있다.
  범례가 직접 라벨을 달고 있어 오독으로 이어지지는 않는다

### 7.3 이중 축 제거

현재 주기별 막대는 **지출=왼축 카테고리 스택 / 수입=오른쪽 보조축**이다(`index.html:2182` `yInc`).
두 축은 배율을 임의로 정하는 순간 없는 상관관계를 만들어내므로 제거한다.

- `yInc` 축과 수입 데이터셋을 **삭제**, 막대는 카테고리 스택 지출만
- `incomeByPeriod`는 `_anStash`에서 계속 계산하되 **차트가 아니라 요약 스탯 텍스트**로 노출
- 수입 정보는 내역·계좌 탭에 이미 있어 손실이 작다

### 7.4 테마 연동

- `drawAnalysisCharts` / `drawTaxChart`의 하드코딩 hex(`tickC` `gridC` `subC` `borderColor:"#0E1020"` 및
  `TY_COLOR`)를 **`getComputedStyle(document.documentElement).getPropertyValue(...)`로 읽는다**
- 도넛 세그먼트 `borderColor`는 서피스 색(`--bg`)을 읽어 **2px 서피스 갭**을 유지
- **`matchMedia('(prefers-color-scheme: dark)')`에 `change` 리스너**를 달아 테마가 바뀌면
  현재 탭이 `analysis`일 때만 `destroyCharts()` → 재렌더.
  ⚠️ `drawWhenChartReady`의 `_renderSeq` 대조 규약을 그대로 통과시킬 것

## 8. 구현 방식

CSS 블록은 42–790행 748줄이고 토큰이 200회 이상 참조된다.
**부분 Edit을 누적하지 않고 `<style>` 블록을 통째로 재작성**한다.

근거: `CLAUDE.md` 기록 — *"Edit 도구는 old_string에 BOM 등 특수문자가 있으면 이스케이프 치환을 시도하다
new_string의 한글을 `\uXXXX` 리터럴로 망가뜨린다 → 그런 줄 근처를 고칠 땐 Write로 전체 재작성."*
한글 주석이 촘촘한 블록이라 실제 위험이 있다.

JS 마크업 변경은 함수 단위로 나눠 진행한다(§6의 함수 목록이 작업 단위).

⚠️ `innerHTML`에 들어가는 사용자 문자열은 `esc()`, `onclick` 인자는 `jsq()` — 마크업을 다시 쓰면서
빠뜨리기 쉬운 곳이다. 기존 호출을 옮길 때 함께 옮긴다.

## 9. 검증

**기존 스크립트 (전부 통과해야 한다)**

| 명령 | 무엇을 막는가 |
|---|---|
| `node scripts/measure_load.js` | 총 바이트 1MB 미만 · Pretendard가 dynamic-subset인가 · Google Fonts 부활 · chart.js가 초기 로딩에 없는가 |
| `node scripts/test_lazy_chart.js` | chart.js 지연 로드 배선 + `<head>` 태그 순서 |
| `node scripts/check_authgate.js` | 로그인 게이트 배선이 소스에 남아 있는가 |
| `node scripts/check_assets.js` | 배포본에 앱 외 파일이 서빙되는가 |
| JS 문법 검사 1줄(`new Function`) | 마지막 `<script>` 파싱 |

**새로 만드는 것 — `scripts/check_theme.js`**

디자인 규칙은 시간이 지나면 조용히 되돌아온다. 문자열이 아니라 **구조**를 검사한다:

1. `:root`에 §3 토큰 12개가 **라이트 값으로** 정의돼 있는가
2. 다크 값이 `@media (prefers-color-scheme: dark)` **안에만** 있는가 (수동 토글 없음 확인)
3. 금지 패턴이 0건인가 — `backdrop-filter` / `background-clip:text` / `font-weight:900` /
   `text-transform:uppercase` / `<style>` 안의 `linear-gradient`·`radial-gradient`
4. `:root` 블록 **바깥**에 생 hex(`#rrggbb`)가 없는가 (토큰 우회 방지)
5. `catColor`가 `% ` 순환을 쓰지 않는가 · 차트 계열 상한이 6인가

⚠️ **일부러 깨서 FAIL이 나는지 확인한다.** `CLAUDE.md` 기록대로 `check_authgate.js`가
문자열 앵커라 주석에만 남아도 우연히 통과한 전례가 있다.

**렌더 검증 — `scripts/shot_theme.js`**

Edge + CDP로 `Emulation.setEmulatedMedia`를 라이트/다크로 바꿔가며 6개 탭을 캡처하고,
같은 세션에서 `getComputedStyle`로 실제 대비를 재서 §3 표와 대조한다.
목업에 쓴 스크립트가 이미 동작을 확인했다.

**성능 회귀**

`node scripts/measure_timeline.js --4g`로 구간 분해. 기준선(`CLAUDE.md`: 4G+CPU4배 DCL 1,102ms / FCP 1,128ms / 384KB).
⚠️ **1회 측정으로 판정하지 않는다** — 개선 전/후를 교대로 N회씩 돌려 중앙값으로 본다.
이번 변경은 그라디언트·블러·그림자를 걷어내므로 페인트 비용이 줄면 줄었지 늘 이유는 없다.
다만 `apple-touch-icon` 재생성 시 **바이트가 늘지 않는지**는 확인해야 한다.
